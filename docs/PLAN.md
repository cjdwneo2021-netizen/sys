# 구현 계획과 확장 지점

## 동작 순서

1. 시간 단위 Actions가 Drive 자료 폴더를 조회한다.
2. 두 번의 관찰에서 지문이 같고 수정 후 안정 기간이 지나면 내려받는다.
3. 다운로드 후 파일 버전 및 전체 폴더를 다시 확인한다.
4. 안정된 원본을 불변 스냅샷으로 저장한다.
5. 노트북 코드·텍스트·짧은 출력과 녹취를 추출한다. 노트북 코드는 실행하지 않는다.
6. 작은 묶음 정리 → 부분 병합 → 강의 공부 노트 생성.
7. 개념 기억·질문 기록·README·다운로드 ZIP 생성.
8. 결과와 처리 체크포인트를 Git으로 기록한다.

## 자료와 일관성

- materials에는 Drive 원본 스냅샷과 최신 manifest를 둔다.
- notes에는 강의별 공부 노트를 둔다.
- memory/concepts에는 정규화한 개념명으로 고정 ID를 가진 Markdown을 둔다.
- memory/questions.md는 강의별 질문 기록이다.
- state에는 관찰 지문, API 호출 수, 부분 정리, 최종 결과와 고정된 기억 문맥을 둔다.
- downloads ZIP에는 공부 노트와 출처 목록을 담는다.

원본 스냅샷을 유지해 갱신 이전 노트의 출처가 사라지지 않게 한다.
Drive에서 강의 폴더가 삭제됐다고 Git 기록을 자동 삭제하지 않는다.
스냅샷과 체크포인트가 누적되므로 장기 사용 시 보존 기간/정리 작업을 추가할 수 있다.

## 기억

모델이 반환한 개념명·설명·원본 SOURCE ID를 검사한다.
모든 출처 ID는 현재 강의의 실제 셀·파일 ID에 포함돼야 한다.
같은 강의에서 등장한 개념은 관련 문서로 연결하며, 선행 관계라고 단정하지 않는다.
다음 강의는 단어가 겹치는 기존 개념 일부를 읽는다.
동의어 자동 통합·벡터 검색·학습자 피드백 반영은 이후 확장한다.

## 비용·재개

파일이 같으면 다시 호출하지 않는다.
노트북의 UI 메타데이터나 실행 횟수만 바뀌어도 다시 호출하지 않는다.
호출 횟수, 출력 토큰, 한 실행의 시간을 제한한다.
호출 완료 결과는 저장하므로 다음 예약 실행에서 재사용한다.
무료 한도 초과 시 더 비싼 모델로 자동 전환하지 않는다.
긴 강의는 하루 호출 한도 때문에 하루 이상 걸릴 수도 있다.

## 검증과 운영

자동화 쓰기는 concurrency 그룹으로 직렬화한다.
동시에 사용자가 main을 수정하면 push는 실패할 수 있으며 다음 실행에서 재처리한다.
별도 push 이벤트를 연쇄 호출하지 않아 봇 커밋 반복 실행을 막는다.
테스트는 외부 호출 없이 수집 안정성·원본 보존·재개·출처·ZIP·노트북 설정을 확인한다.

## 확장

Google Drive client, 자료 추출, 모델 backend, 렌더링을 모듈로 분리했다.
동일 CLI를 다른 서버리스 런타임이나 개인 PC로 옮길 수 있다.
OpenAI 호환 API를 지원하는 로컬 모델 서버를 연결할 수 있다.
초기 버전은 음성 전사, PDF OCR, 역방향 Drive 동기화, 코드 자동 수정·PR 생성을 하지 않는다.
